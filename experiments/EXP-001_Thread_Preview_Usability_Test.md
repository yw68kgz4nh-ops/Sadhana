# EXP-001 — Active Thread Indicator and Thread Preview Usability Test

**Status:** 🟠 Amber — test plan drafted; no participants or results recorded.  
**Related use case:** SA-UX-006 — Active Thread Indicator and Long-Press Context Preview.

## Question

Can an active-thread indicator and a non-navigating preview help people identify the correct conversation faster and with fewer accidental thread switches?

## Hypothesis

Compared with a conversation list that relies mainly on titles, a clear active-thread indicator plus an accessible preview will reduce wrong-thread selections and unnecessary thread openings without adding significant interaction burden.

## Prototype conditions

- **A — Baseline:** conversation list with titles only.
- **B — Indicator:** list with a clearly marked active conversation.
- **C — Indicator + preview:** active marker and preview showing purpose, latest work, latest user input, and freshness information.

For preview access, compare long-press with a discoverable alternative (such as a context-menu action or preview control). Do not assume hover is available or suitable on every device.

## Participants and task

Recruit a small, varied pilot group before any broad claims. Ask participants to imagine they have about twelve active threads and need to find the thread where they last worked on a named task, without losing the work in their current thread.

## Measures

- Time to identify the correct thread.
- Number of threads opened unnecessarily.
- Wrong-thread switches.
- Whether the preview accurately reflects the supplied thread.
- Confidence about which thread is active.
- Discoverability, accidental activations, and accessibility barriers.
- Preference and rationale, not preference alone.

## Procedure

1. Define success thresholds before collecting results.
2. Give participants the same task under each condition, counterbalancing order where practical.
3. Observe without teaching the interaction unless the test is specifically measuring learnability after instruction.
4. Record task outcomes and direct quotes with consent; do not collect unnecessary personal information.
5. Review failures and alternative explanations before recommending a design.

## Success criteria

Set numeric thresholds with the project team before testing. At minimum, the preferred design must reduce wrong-thread errors or unnecessary openings without materially increasing task time or accessibility problems. Report small-sample results as exploratory, not universal proof.

## Results

**Not run.** No participant data, timings, or findings are claimed.

## Next step

Build a low-fidelity clickable or paper prototype, write the task script, and agree measurable thresholds before recruiting participants.
